## 2024-04-29 - [Fix XSS Vulnerabilities in DOM Attribute Interpolation]
**Vulnerability:** Cross-Site Scripting (XSS) vectors were present due to insecure string interpolation in HTML attributes (like `src`, `alt`, and `class`) and `innerHTML` blocks inside `frontend/js/chat.js`. The existing `escapeHtml` function used `div.textContent`, which does not escape quotes (`"` or `'`), leaving dynamic attributes vulnerable to breakout attacks. Also, inline event handlers (e.g., `onclick="loadSession('${chat.id}')"`) cannot be safely protected by standard HTML entity escaping since the browser decodes HTML entities *before* executing the inline JS.
**Learning:** Never rely on `textContent` for escaping strings meant for HTML attribute interpolation. HTML entity escaping is ineffective for inline event handlers (like `onclick`) because the browser decodes attributes to strings before execution, meaning properly escaped quotes (e.g., `&#39;`) revert to real quotes (`'`), allowing JS breakouts.
**Prevention:** Use a dedicated `escapeAttribute` function (or `dataset` mappings) when injecting data into standard HTML attributes. For dynamically generated list items requiring event handlers, completely avoid `innerHTML` string interpolation for inline JavaScript. Instead, construct elements via `document.createElement`, set text content with `.textContent`, and attach behavior natively using `element.onclick = () => { ... }`.
