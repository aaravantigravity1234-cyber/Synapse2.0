## 2025-05-18 - Fix Permissive CORS and Missing Security Headers
**Vulnerability:** The Express backend used a completely permissive CORS configuration (`app.use(cors())`) and was missing essential security headers (like HSTS, X-Content-Type-Options, X-Frame-Options) while exposing the `X-Powered-By` header.
**Learning:** Overly permissive CORS can allow any origin to make cross-origin requests to the API, potentially leading to CSRF or data leakage if combined with credentialed requests or other flaws. Missing security headers leaves the application open to MIME-sniffing, clickjacking, and XSS attacks. Exposing `X-Powered-By` gives attackers information about the technology stack (Express) which can be used to target specific vulnerabilities.
**Prevention:** Always restrict CORS to explicitly trusted origins (e.g., the frontend URL). Apply standard security headers (either via a library like `helmet` or custom middleware) and explicitly disable technology-identifying headers (`app.disable("x-powered-by")`).
